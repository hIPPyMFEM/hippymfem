Verification and validation
===========================

Nothing in this library is checked only against itself.  Four independent references
are used, and each caught defects the others did not.

Against MFEM's own integrators
------------------------------

Every block generated by automatic differentiation is compared against the
hand-written MFEM integrator for the same bilinear form, on the **same integration
rule** (set explicitly with ``SetIntRule``, or the comparison measures the rule
difference instead).

.. list-table::
   :header-rows: 1
   :widths: 38 42 20

   * - form
     - MFEM integrator
     - agreement
   * - ``inner(grad u, grad p)``
     - ``DiffusionIntegrator``
     - 2e-16
   * - ``u p``
     - ``MassIntegrator``
     - 2e-16
   * - elasticity
     - ``ElasticityIntegrator``
     - 5.5e-16
   * - ``dot(u, p)``, H(curl)/H(div)
     - ``VectorFEMassIntegrator``
     - 1.3e-15
   * - ``curl u . curl p``
     - ``CurlCurlIntegrator``
     - 1.0e-15
   * - ``div u div p``
     - ``DivDivIntegrator``
     - 1.4e-15
   * - boundary ``u p``
     - ``MassIntegrator`` as a boundary integrator
     - 2.6e-16
   * - boundary ``dot(grad u, n) p``
     - ``BoundaryNormalLFIntegrator``
     - 2.5e-16

on triangles, quadrilaterals, tetrahedra and hexahedra, P1 to P3, scalar and vector,
including mixed-geometry meshes and the H(curl) case that needs a
``DofTransformation``.

Blocks taken *between two families* are checked the same way: the ``RT`` mass and the
``L2`` x ``RT`` divergence of a mixed Darcy density against ``VectorFEMassIntegrator``
and ``VectorFEDivergenceIntegrator`` (worst 1e-12), with the two off-diagonal blocks
required to be each other's negative transpose, and the diagonal blocks of a
poroelasticity density against ``ElasticityIntegrator`` and a mass-plus-diffusion pair.

Against hIPPYlibx on a shared discrete problem
-----------------------------------------------

``validation/run_validation.sh`` solves the *same discrete problem* in hIPPyMFEM and in
`hIPPYlibx <https://github.com/hIPPyMFEM/hippylibx>`_ (hIPPYlib on FEniCSx): the same mesh
arrays, the same quadrature degree, the
same observation points, and the same noise realization read from a file written by
whichever driver runs first.  The two run under different interpreters because they need
different environments.

Twenty-seven quantities agree.  The decisive one is the **exact dense generalized
spectrum of the misfit Hessian**, evaluated at a fixed analytic point so that neither
optimizer enters the comparison: **3.7e-13**.  Costs, gradients, Hessian quadratic
forms, the MAP point and the MAP fields agree to 1e-13 to 1e-15.

Internal consistency
--------------------

* adjoint identities, and symmetry of every second-order block;
* ``ReducedHessian`` against ``FDHessian``;
* ``modelVerify`` slopes of exactly 1 for the gradient and the Hessian;
* BFGS reproducing the Newton-CG minimizer to 1e-5, from the cost and gradient alone;
* randomized eigensolvers against a dense ``eigh`` (1e-15);
* :math:`\sqrt{M}\sqrt{M}^{\top} = M` exactly;
* MCMC against an **exact Gaussian posterior**, and the autocorrelation time against
  an AR(1) process whose value is known analytically;
* the full Hessian positive definite **at the MAP point** over several directions,
  though not everywhere, because away from a minimum it is legitimately indefinite.

Implementation equivalences
---------------------------

Where a faster path replaced a slower one, the slower one is kept as the reference
and the two are required to agree *exactly*:

* direct-CSR assembly against MFEM's per-element callback route: **exactly zero**
  difference for every block, every geometry, every diagonal policy, on 1, 2 and 4
  ranks;
* GPU against CPU element kernels and assembled operators: 4.3e-16 and 3.6e-16;
* the deterministic device scatter against the atomics-based one: 1e-16;
* exact parallel solves against iterative ones on the same inverse problem.

Partition independence
----------------------

Random vectors are bit-identical on 1, 2 and 4 ranks, because the random stream is
indexed by global position rather than by rank.  Prior samples, synthetic data and the
MAP point pass through linear solves, so they agree across rank counts to the tolerance
of those solves: to round-off with the exact solvers, and to 1e-14 for a prior sample
whose Krylov solve is run to that tolerance.  This is the check that catches ghost-dof
and true-dof mistakes, which symmetry tests do not.
